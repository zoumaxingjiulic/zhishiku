# 企业智能体平台全局设计

## 1. 平台定位与边界

平台不是“知识库加聊天框”，而是企业员工访问 AI 能力、业务数据和自动化流程的统一入口。知识库继续负责非结构化资料的治理、检索与引用，本设计只定义知识库与其他平台能力之间的边界，不展开知识库内部细节。

平台按四层演进：

1. **统一入口层**：工作台、智能体目录、个人提示词、智能体申请、管理后台。
2. **智能体运行层**：问答、表单任务、工作流、数据看板、外部应用五类运行容器。
3. **平台能力层**：大模型网关、知识检索、连接器、工具调用、权限、审计、任务队列和人工确认。
4. **基础设施层**：MySQL、Redis、MinIO、Milvus、OpenSearch、本地模型、外部模型 API 与企业业务系统。

## 2. 信息架构与权限

| 模块 | 员工 | 平台管理员 |
| --- | --- | --- |
| 工作台 | 查看本人可用能力与任务 | 查看平台概览 |
| 知识库 | 按部门 ACL 使用或管理 | 全局管理 |
| 智能体 | 使用管理员分发给本人的智能体 | 查看、配置并向具体用户分发全部智能体 |
| 提示词模板 | 管理自己的私有模板 | 同样只管理自己的模板，不越权查看员工内容 |
| 智能体申请 | 提交并查看自己的申请 | 查看全量申请、评审、推进与关闭 |
| 系统连接 | 查看可用连接能力 | 配置、发现、启停和审计 MCP 连接器，并向账号直授或向专业智能体绑定只读工具 |
| 大模型网关 | 不可见、API 返回 403 | 配置厂商 API、模型档案和智能体路由 |
| 用户、部门、审计 | 不可见 | 全局管理 |

敏感控制遵循三条原则：模型和系统凭据加密保存且永不回显；每次模型调用、系统查询和流程关键动作记录审计；任何写回 ERP、PLM 等生产系统的动作默认需要显式工具授权和人工确认。

## 3. 智能体模型

智能体由“入口 + 配置 + 工具 + 数据权限 + 运行记录”组成，不把所有智能体都塞入问答接口。

| launch_mode | 交互形态 | 典型场景 |
| --- | --- | --- |
| `chat` | 多轮对话 | 制度问答、技术资料助手、数据问答 |
| `form` | 参数表单 + 单次任务 | BOM 对比、报表生成、批量分类 |
| `workflow` | 多步骤状态流转 | 采购检查、变更评审、跨系统处理 |
| `dashboard` | 指标与异常列表 | 库存风险、质量趋势、项目进度 |
| `external` | 平台内嵌或跳转 | 已有业务应用的统一入口 |

智能体通过 `user_agent_acl` 分发给具体用户，不按部门分发。用户启动已分发智能体后，仅在该智能体任务内临时使用 `agent_knowledge_base` 和 `agent_connector_tool` 绑定的启用知识库与只读工具；这些能力不会扩散到企业总助手、其他智能体或知识库管理接口。模型通过 `llm_gateway_profile_id` 路由；连接业务系统时通过受控工具引用连接器，不在智能体配置里保存系统密码。

## 4. 大模型网关

`llm_gateway_profile` 表示一个可复用的模型调用档案，包括厂商、兼容接口地址、模型名、能力标签、非敏感参数和加密 API Key。智能体可独立绑定档案，未绑定的存量智能体暂时回退到服务器环境变量，便于平滑迁移。

后续网关执行面应增加：连接测试、超时与重试、并发和额度限制、失败熔断、调用量与成本统计、输入输出脱敏、模型白名单、按部门成本中心分摊，以及主备模型降级策略。

## 5. 企业系统连接器

当前版本已实现 MCP Streamable HTTP 连接、Bearer Token 加密存储、`tools/list` 能力发现、工具 JSON Schema 持久化、账号直授、智能体绑定和只读工具运行。ERP U9 与 OA 通讯录作为首批连接；后续 PLM/MOM 延续同一接入规范。

收到 ERP、PLM、MOM 等接口资料后，每个系统按同一规范接入：

1. 建立连接器实例，配置网络地址、认证方式和密钥引用。
2. 建立工具定义，声明入参、出参、只读/写入属性、超时、幂等键和所需权限。
3. 做字段映射和数据分级，禁止将超出当前用户权限的数据送入模型。
4. 只读查询可在授权范围内自动执行；写操作、审批和批量变更进入人工确认节点。
5. 记录调用人、智能体、工具、业务主键、耗时、结果摘要和错误，不在日志中记录凭据或敏感正文。

连接器建议分为实时查询、增量同步和事件订阅三种方式。实时查询适合库存、订单等新鲜数据；增量同步适合分析与检索；事件订阅用于触发流程智能体。智能体只依赖标准工具契约，厂商接口变化由连接器适配层消化。

## 6. 复杂智能体运行原则

本项目不建设低代码工作流平台。复杂业务以经过测试的专业智能体和确定性代码工具实现；长任务实例独立于聊天消息，至少包含配置版本、发起人、输入输出、工具调用、必要的人工确认、重试、状态和完整时间线。推荐状态为 `draft → running → waiting_approval → succeeded|failed|cancelled`。

每一步都要满足可重放、可恢复和幂等。模型负责理解、分类、生成建议或结构化参数；确定性的校验、金额计算、权限判断和系统写入由代码工具完成，不能只依赖模型文本。

## 7. 交付路线

### 第一阶段：平台骨架（当前代码）

- 新导航和角色可见性。
- 员工私有提示词 CRUD。
- 智能体申请与管理员评审。
- 加密模型档案和按智能体模型绑定。
- 紧凑智能体目录与五类运行形态。

### 第二阶段：管理与运行闭环

- 智能体创建、编辑、版本发布、用户分发和停用。
- 模型连通性测试、调用审计、用量与成本。
- 流程定义、运行实例、人工确认和任务中心。

### 第三阶段：首批业务系统接入

- 根据接口文档建立连接器与字段权限映射。
- 先实现只读工具与验收数据，再开放需确认的写入工具。
- 选择一个高价值、低风险流程智能体做端到端试点。

### 第四阶段：企业级治理

- SSO、细粒度 RBAC/ABAC、数据分级与脱敏。
- 高可用、备份恢复、监控告警、容量与成本治理。
- 智能体评测集、发布门禁、质量反馈和版本回滚。

## 8. 接口资料交接清单

后续提供系统接口时，至少需要：环境地址与网络限制、认证方式、接口文档或 OpenAPI、测试账号、字段字典、分页与限流规则、错误码、可用测试数据、数据权限规则，以及哪些操作允许写入。生产凭据不要写入代码仓库或对话正文，应通过服务器受控环境注入。
