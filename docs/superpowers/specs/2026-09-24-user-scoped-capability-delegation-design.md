# 用户级能力授权与智能体临时委托设计

日期：2026-09-24
适用基线：`0478735`

## 1. 目标

把当前“部门决定大部分能力、企业总助手还能间接调用专业智能体”的模型，调整为三个清晰边界：

1. 用户在企业总助手中只能使用其部门继承与管理员直接授予的知识库，以及管理员直接授予的只读 MCP 工具。
2. 专业智能体只分发给具体用户；被分发后，用户在该智能体会话内可临时使用智能体绑定的知识库和只读 MCP 工具。
3. 智能体临时能力不扩散到企业总助手、其他智能体、知识库管理页面、下载接口或直接 MCP 接口。

本轮不建设部门级智能体分发、授权模式、必需/可选能力、受限模式或低代码工作流。

## 2. 权限来源

### 2.1 用户永久权限

用户永久权限由两部分组成：

- 部门继承：沿用 `knowledge_base_department_acl`。本部门知识库的 `manage` 权限允许上传、目录维护、重建与删除资料。
- 用户直授：管理员通过账号创建/编辑页维护额外知识库权限和只读 MCP 工具权限。

新增关系：

```text
user_knowledge_base_acl(user_id, knowledge_base_id, permission)
user_connector_tool_acl(user_id, connector_tool_id, permission)
```

知识库权限取部门继承与用户直授的并集；同一知识库出现多条来源时，`manage` 高于 `read`。工具第一版仅允许 `readOnlyHint=true` 的工具，数据库权限值固定为 `use`。

### 2.2 智能体分发

专业智能体只分发给具体用户：

```text
user_agent_acl(user_id, agent_id, permission='use')
```

平台管理员可测试所有已启用智能体；普通用户必须存在有效的 `user_agent_acl`。不再根据部门或知识库重叠推断用户能否看到智能体。

已有启用部门的 `agent_department_acl` 在迁移时一次性展开成用户级授权，以免现有用户突然失去入口。新代码不再读写该表；该表仅保留一个兼容周期作为审计和回填来源，不能作为新权限模型的回滚来源。出现问题时优先前向修复；若权限已经在新版本中发生变化，不允许只回滚应用代码。

### 2.3 智能体临时委托

用户进入已获授权的专业智能体后，运行时生成仅限当前智能体、当前用户、当前任务的能力上下文：

```text
actor_user_id
agent_id
session_id / task_id
allowed_knowledge_base_ids = agent_knowledge_base
allowed_tool_ids = agent_connector_tool 中的只读工具
expires_at
```

每次检索和工具调用都同时校验：用户仍可使用该智能体、智能体仍启用、能力仍绑定、任务仍属于当前用户。任何一个条件变化都立即拒绝后续调用。

临时委托只允许：

- 在该智能体回答流程中检索绑定知识库；
- 在该智能体回答流程中调用绑定的只读 MCP 工具。

临时委托不允许：

- 打开、下载、上传、编辑或删除未永久授权知识库的资料；
- 直接调用连接器工具 API；
- 把能力带到企业总助手或其他智能体；
- 调用写工具。

## 3. 企业总助手边界

企业总助手的能力目录改为：

```text
知识库 = 部门继承知识库 ∪ 用户直授知识库
MCP 工具 = 用户直授的启用只读工具
Skill = 仅保留不依赖专业智能体、且其全部知识库/工具都在上述永久权限内的 Skill
专业智能体 = 空
```

意图识别输出不再接受 `agent_ids`，编排器不再执行专业智能体或通过 Skill 间接委托智能体。一般聊天、知识检索、只读系统查询和合规的声明式 Skill 保留。

## 4. 账号管理体验

管理员创建或编辑账号时配置：

- 主部门；
- 由主部门继承的知识库权限（只读展示来源，不能在账号页面取消）；
- 额外知识库权限（可选 `read` 或 `manage`）；
- 可使用的只读 MCP 工具。

后端始终重新计算部门继承权限，前端展示只用于解释，不作为授权依据。用户修改部门后，继承权限即时按新部门变化，直授权限保持不变。

智能体工作室把“使用部门”改为“分发用户”，并继续配置智能体绑定的知识库和只读工具。这里配置的是智能体运行权限，不改变用户永久权限。

## 5. 数据与 API

新增迁移 `014_user_scoped_capabilities.sql`，只新增三张授权表并从 `agent_department_acl` 回填 `user_agent_acl`，不修改文档、切片、Milvus 集合、OpenSearch 索引或 MinIO 对象。

账号写入接口在原字段之外接受：

```json
{
  "knowledge_base_grants": [
    {"knowledge_base_id": 3, "permission": "read"}
  ],
  "tool_ids": [12, 15]
}
```

账号详情返回部门继承、用户直授和最终有效权限，列表接口保持轻量。所有授权替换和账号资料更新处于同一数据库事务中。

智能体写入接口把 `department_ids` 替换为 `user_ids`。读取旧字段只在迁移/兼容层内处理，不再向前端暴露部门分发。

## 6. 安全不变量

1. 前端传来的知识库、工具和智能体 ID 永远不能直接作为授权依据。
2. 普通用户不能给自己授予权限；只有平台管理员可维护直授关系和智能体分发。
3. 用户直授工具必须启用、所属连接器启用且为只读工具。
4. 智能体临时委托不能进入通用知识库服务或通用连接器接口，只能由智能体运行时内部适配器使用。
5. 权限检查至少发生在能力目录构建、任务提交和实际检索/调用三个位置。
6. 删除用户、知识库、工具或智能体时，授权关系由外键级联清理。
7. 授权变更写入审计日志，日志不记录 Token、密码或连接器密钥。

## 7. 验收场景

- 人资员工默认可管理人资知识库，不需要管理员逐项勾选。
- 技术部员工可被额外授予人资知识库只读权限，但不能管理人资资料。
- 普通员工未获得人资知识库永久权限时，企业总助手不能检索人资知识库。
- 同一员工被分发“人资制度问答助手”后，可以在该智能体内查询婚假；离开该智能体后仍不能直接浏览人资知识库。
- 撤销智能体分发后，新任务与正在进行任务的下一次能力调用均被拒绝。
- 企业总助手的意图结果和执行时间线中不再出现专业智能体委托。
- 智能体绑定的只读工具可以在该智能体内调用，但用户不能从企业总助手或直接 API 调用，除非另有用户直授。
